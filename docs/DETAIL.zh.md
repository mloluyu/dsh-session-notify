# 会话完成通知

当顶层会话完成任务、出错、被取消、停下等待你输入，或需要你授权/回答提问时通知你。通知标题是会话名，全部通知都由页面发出（本插件没有宿主进程通知——页面没开就没有提醒，这是设计使然）：

- **页面有焦点、但你开着的是别的会话/面板** → 页面右上角弹出应用内通知卡片（不透明，自动消失）。
- **页面有焦点、且你正看着触发事件的这个会话** → 什么都不弹（现场就在眼前）。
- **页面无焦点** → 页面发出一条系统通知（浏览器 Notification API）。桌面端里 Electron 把它以 DSH 本体身份送进通知中心——鲸鱼图标、系统设置里只有本体一个条目；在普通浏览器里打开 Web 界面时归属该浏览器。

## 什么时候触发

插件监听整个 agent 生命周期，有两类时刻会通知：

**回合结束**：只有真实的 `running → idle` 转变、且在宽限期内（默认 1500 ms）保持 idle 才会通知。如果 agent 在宽限期内接上了排队的后续输入或 goal 续跑轮次，待发的通知会被取消，因此多回合连续运行和后台循环不会每个回合都弹一条通知。通知标题为会话名（来自 `session/title` 事件；尚无标题时回退到工作区文件夹名，再回退到应用名），正文反映最后一个回合的结束原因：

| 结束原因 | 默认正文 |
|---|---|
| `completed` | 任务完成 |
| `error` | 运行出错：…（失败信息前 120 字符） |
| `aborted` | 已取消 |
| `blocked` | 等待你的输入 |
| `max-tokens` | 达到输出上限 |
| 其他类型 | 任务已结束 |

**运行中的交互请求**（立即通知，不等 idle）：会话弹出工具授权请求（`approval/request`）或用户提问（`user-questions/request`）时：

| 事件 | 默认正文 |
|---|---|
| 工具授权 | 等待你的授权：…（工具名） |
| 用户提问（单个） | 等待你的回答：…（问题文本） |
| 用户提问（多个） | 等待你的回答（N 个问题） |

## 通知范围

- 只有顶层会话会通知。`origin: subagent` 或 `delegationDepth > 0` 的会话（委派的 subagent 工作）被排除。
- 冷恢复后直接处于 idle 的 agent 不会通知，因此应用启动不会产生通知风暴。
- 页面（GUI 标签页/窗口）关闭期间不发送任何通知。若希望页面关闭时也有提醒，需要宿主侧通知器，本插件刻意不做。

## 实现

- `client.js`（页面内）：注入 `sessions`/`remote`/`uiSession` 服务；通过 `api-session/status` 推送跟踪会话 running 状态，用 `uiSession.adapter.current` 判断你正盯着哪个会话；运行中的授权/提问走 `approval/request`、`user-questions/request` 两个 remote 推送通道；卡片为纯 DOM，深浅色自适应；系统通知走 `Notification` API，首次触发会向浏览器/应用请求权限。
- `index.js`（宿主侧）：刻意的 no-op，只为了让 bundle 注册为 host 插件、GUI 才会加载 client 半边。

无配置项——所有行为由 client.js 顶部的 `DEFAULTS` 常量决定（卡片开关/时长/堆叠上限/宽限时长/回退标题），需要调整直接改源码。bundle 零外部依赖、零子进程。
